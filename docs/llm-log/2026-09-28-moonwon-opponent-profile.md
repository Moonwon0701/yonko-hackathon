## 목적

- 흉내 봇을 만들기 전에, 강팀이 우리와 무엇이 다른지 리플레이 수치로 확인한다.

## 범위 — LLM이 한 것

- PR #49를 머지하고 브랜치를 정리했다. `main`을 테마 브랜치에 합쳤다.
- `scripts/profile_opponents.py`를 새로 만들었다. 리더보드 3회차(9/27 22:00, 9/28 10:00·22:00) 리플레이 36판에서
  상대(또는 `--us`로 우리)의 깃발병·전투병 수, 남긴 자원, 전투병 배치(칸 수·칸당 인원·상대 본진 쪽 비율), 점령 순서,
  광장 점령 턴, 중립화 횟수를 뽑는다. `--economy`는 20~80턴 전투병 생산량과 공학관 쟁탈을 뽑는다.
  생산량은 우리 `SPAWN W` 명령과 "전투병은 같은 칸에서 같은 수만큼 죽는다"는 규칙으로 양쪽 모두 역산한다.
- `docs/benchmarks.md` "서버 리더보드" 표에 분석 결과 한 줄을 더했다.
  - 합계 수치(깃발병 수, 20턴 전투병, 남긴 자원, 정찰병, 전투병을 까는 넓이)로는 강팀과 우리가 거의 같다.
  - 진 11판 중 4판은 20~80턴 상대 전투병 생산이 46~99명 많았다. 유닛에 쓴 자원은 비슷했다.
  - 진 11판 중 5판은 우리 공학관을 빼앗겨 전투병 값이 3인 턴이 25~74%였다. 이긴 25판 중 19판은 상대 공학관을 빼앗았다.
  - 결론: 흉내 봇은 스타일 합계가 아니라 경제 건물(공학관·학생회관) 쟁탈을 재현해야 한다.
- 분석 도중 처음에 세운 가정("1:1 상쇄라 전투병 차이 = 생산량 차이인데 쓴 자원이 같다")이 맞지 않아, 명령 기록으로
  생산량을 다시 셌다. 이긴 경기 수를 17판으로 잘못 적었다가 다시 세어 19판으로 고쳤다.

## 사람이 한 것

- 문원: 테마(평가·튜닝)와 1단계(흉내 봇) 진행을 정했다.

## 검증

- `--economy` 출력이 따로 계산한 값과 같다(AIKU 9/28 10:00 생산 294:393, 22:00 284:343 등).
- `ruff check scripts/profile_opponents.py` 통과.
- 생산량은 요청한 `SPAWN` 수로 세므로, 자원이 모자라 덜 만든 턴이 있으면 우리 생산을 조금 크게 센다. 유닛에 쓴 자원 비교는
  수입 모델(기본 10 + 학생회관 2, 보급소 15)로 근사한 값이다.
