# 유닛 운용 분석과 실험 스위치 (모아서 들어가기·요격·비용 교환·1명 과제)

- 날짜: 2026-09-29
- 요청한 사람: 문원
- 모델: Claude Opus 5.5 (`claude-opus-5-5`), Claude Code CLI
- PR: 없음 (실험 브랜치 `moonwon/unit-ops`, `moonwon/merge-squad` `6bb20e4`에서 시작)

## 프롬프트 (원문 그대로)

1. > 다른 브랜치에서 현진 + 내 자체 개발 머지 진행하고 있어. 다른 아이디어 더 내보자. 유닛 운용 측면에서 고민해봐도 될 것 같아
2. > 전부다 실험해봐
3. > 얼마나 걸려
4. > 배터리가 없어. 일단 실험 종료해줘

## 목적

- 서버 리플레이에서 유닛 운용의 약점을 찾고, 그 결과로 낸 아이디어 4개를 스위치로 넣어 시험한다

## 범위 — LLM이 한 것

- 분석(일회용 스크립트, 저장소에 넣지 않음): 서버 리플레이 48판 10~80턴 전투 6155건을 우리 명령 줄로 전투 전 인원을 복원
  - 전투의 36%에 우리가 전투병 1명으로 들어가 승 8%(6명 이상 71%). 상대가 먼저 있던 칸에 들어간 전투 55% 패(2.6 : 7.5),
    진 전투의 약 절반은 직전 턴 2칸 안에 우리 전투병이 더 있었음. 로컬(현진 봇 상대 50경기)도 1명 전투 42%, 승 2%
  - 우리 건물이 중립이 된 경로(1~80턴 경기당): 상대 깃발병의 중립화 9~12회, 건물 위 깃발병 전사 2회
- `agent/strategy.py`에 스위치(모두 기본 끔): `STAGE`(1 = 적 전투병이 선 과제 칸 앞에서 전원 도착까지 대기, 2 = 1 + 적이 더
  많은 칸에 안 들어감), `INTERCEPT_IDLE`·`INTERCEPT_VALUE`·`INTERCEPT_RADIUS`(적 깃발병의 예상 목적지 건물로 먼저 감),
  `TRADE_BOOST`·`TRADE_KINDS`(전투병 값이 싸면 공격 과제 가치를 올리고 비싸면 내림), `PICKET_NEED`·`ESCORT_NEED`

## 사람이 한 것

- 유닛 운용 쪽 아이디어를 요청하고, 네 가지를 모두 실험하기로 결정
- 배터리 문제로 평가를 중간에 멈추기로 결정

## 검증

- 기본값(끔)에서 `sim diff` 20경기 3200턴 명령이 모두 같음. `pytest` 831개 통과
- 끝난 결과(나머지는 멈춤으로 못 돌림)
  - `tune.py --check "STAGE=1" --seeds 50 --seed 3000`: 기준 71.5% → 41.6% (기준 봇 상대 24%, `eng_rush` 34%, `econ_raid` 40%,
    `wide` 80%, `blob` 30%)
  - 현진 봇(`hyunjin/defense-econ`) 상대 시드 7000~7014(30경기): 끔 → `STAGE=2`: 전투 승률 37 → 47%, 1명 전투 37 → 31%,
    경기 승률 50 → 30%. 칸은 더 따내지만 기다리는 동안 깃발병·건물을 놓친다
- 못 돌린 설정: `STAGE=2`(풀), `INTERCEPT_IDLE=1`, `INTERCEPT_VALUE=1.0`, 둘 다, `TRADE_BOOST=1.5`·`2.0`, `PICKET_NEED=2`,
  `PICKET_VALUE=0`, `ESCORT_NEED=2`, `FRONT_NEED=2`

### 프롬프트 (원문 그대로)

1. > 내 브랜치에서 진행중이던 실험 찾아봐
2. > 그거 말고 다른 브랜치 없어?
3. > 고고 해주고 다음 계획도 세워봐
4. > 얼마나 더 걸려?
5. > 기다리는 동안 다음 계획 먼저 정리해줘
6. > unit-ops 브랜치에 올려줘
7. > 진 경기 리플레이 좀 더 구체적으로 분석해보자. 깃발병을 망ㅎ이 뽑는 전략은 자원 소모가 심할것 같아
8. > 공학관에 전투병을 좀 남겨두는 건 어때
9. > 다른 방식은 없나. 좀 더 창의적인 방식
10. > 1번 2번 구현하고 돌려줘
11. > 얼마나 더 걸려?
12. > 공학관 실험 먼저해줘
13. > 우선 실험 결과 푸시해. 로컬 세션에서 다시시작할거야

(1~2는 브랜치 탐색, 5는 다음 계획 정리로 파일 변경 없음. 8에 LLM은 현진 브랜치의 수비대 실험(`a560165`, 1명은 효과 없음·3명은
손해)을 근거로 "항상 남겨 두기"보다 조건부를 제안했고, 9에 규칙(중립화 → 점령 2턴, 공학관 할인 중복 없음, 생산한 유닛은
같은 턴에 이동)에서 네 가지 안(① 탈환 창 ② 공학관 열세 국면 ③ 러시 시간대에만 위협 크기만큼 배치 ④ 자원 비축 후 즉시 생산)을
냈다. 10의 "1번 2번"은 ①·②다)

### 목적

- 멈췄던 유닛 운용 스위치 평가를 끝내고, 리더보드 진 경기의 원인을 자원 흐름으로 확인해 다음 실험을 고른다

### 범위 — LLM이 한 것

- 평가(일회용 스크립트, 저장소에 넣지 않음): `scripts/tune.py`의 `Tuner`·`launcher`로 풀 6개(기준 봇 + 흉내 봇 4 + 현진 봇)
  × 시드 3000~3049 × 진영 2. 공학관 실험은 경기 기록으로 21~80턴 공학관 없는 턴을 함께 셈
- `scripts/replay_economy.py` (새 파일): 리더보드 리플레이에서 양쪽 수입·점령 비용·깃발병/전투병 생산·깃발병 손실을 구간별로 복원
- 분석(파일 변경 없음): 리더보드 48판 공학관 소유 변화와 그때 2칸 안 병력, 생성 맵 300개의 본진·병원 → 우리 공학관 거리
- `agent/strategy.py`: 스위치 두 개(기본 끔) — `RETAKE_VALUE`·`RETAKE_EXTRA`·`RETAKE_MEMORY`·`RETAKE_CAPTURE`(`retake_tasks`,
  `recently_lost`, 턴을 넘어 `_last_owned` 기억), `ENG_DEFICIT`·`DEFICIT_VALUE`·`DEFICIT_EXTRA`·`DEFICIT_CAPTURE`(PHASE_TREE에
  DEFICIT 가지, `eng_focus_tasks`). 국면 조건을 `ctx.active.get`으로 읽게 바꿈(DEFICIT 키가 없는 테스트 입력)
- `tests/test_strategy.py`: 탈환 과제·열세 국면 테스트 2개
- `docs/benchmarks.md`: 파라미터 탐색 표 2줄, 서버 리더보드 표에 자원 흐름 분석 1줄

### 사람이 한 것

- 남은 설정을 모두 돌리고 다음 계획을 세우도록 결정, 결과를 `moonwon/unit-ops`에 올리도록 허락
