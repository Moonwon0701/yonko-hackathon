## 2. 통신 방식

- 방식: **표준 입력(stdin)으로 상태 수신, 표준 출력(stdout)으로 명령 출력.** 한 프로세스가
  경기 시작부터 끝까지 여러 턴을 처리한다.
- 모든 입출력 블록은 마지막 줄 `END`로 끝난다. 명령 출력 후 `END`를 쓰고 **반드시 flush**.
- 행동하지 않는 턴에도 `END`는 출력해야 한다.
- stdout에는 명령만. 디버깅 로그는 **stderr**, 경기당 1 MiB 이하 (160턴이면 턴당 약 6 KB).
- 파일 쓰기·외부 네트워크·추가 프로세스 실행은 제한된다 → 로그 파일을 쓸 수 없다.
- 출력 한도: 턴당 64 KiB · 4,096줄, 줄당 1 KiB.
- 입력을 제때 읽지 않아 서버의 전송이 막혀도 시간 초과로 처리된다.
- `END`를 출력했더라도 프로세스가 이미 끝나 있으면 몰수 → **입력이 끝날(EOF) 때까지 기다려야 한다.**

→ 결정되는 것: `agent/adapter.py` = stdin 파서 + 명령 직렬화. 최상위 `main.py`가 루프를 돈다.

- 참가: 대회 페이지에 ZIP 업로드 → 코드 선택. 서버가 대진을 짠다.
- 경기 시작: 프로세스가 기동되고 `INIT` 블록을 1회 받는다.
- 경기 종료: 160턴 종료, 또는 즉시 승리 조건 달성, 또는 한쪽 몰수.
- 한 경기: 160턴. 경기 전체 시간 상한 3분.

## 4. 틱 / 턴

- 턴제, **양 팀 동시 턴.**
- 시간 제한: 첫 턴 3000 ms (프로세스 기동 + INIT 수신 + 초기화 + 첫 응답 전부 포함),
  둘째 턴부터 **300 ms** (입력 전송 시작 ~ 우리 `END` 수신 완료).
- 시간 초과, 비정상 종료, `END` 누락, 무응답 → **즉시 몰수패.** 양 팀 동시면 무승부.
- CPU 전용, 메모리 384 MiB, 프로세스 최대 32개(단 추가 프로세스 실행은 제한됨).

턴 안의 처리 순서 (전략의 핵심):

| 순서 | 단계 | 내용 |
| --- | --- | --- |
| 1 | 명령 수신 | |
| 2 | 생산 | SPAWN. **지난 턴까지 모은 자원만** 쓸 수 있다 |
| 3 | 이동 | MOVE · MOVE2 · TELE 양 팀 동시 적용. 이동 중 충돌 없음 |
| 4 | 전투 | 양 팀 유닛이 겹친 셀에서만 |
| 5 | 건물 효과 갱신 | |
| 6 | 수입 | 기본 10 + 학생회관당 2, 상한 40 |
| 7 | 점령 | 살아남은 깃발병 기준. 이번 턴 수입으로 비용 지불 가능 |
| 8 | 정보 공개 | 점수 공개 |
| 9 | 승리 판정 | |

- 생산한 유닛은 같은 턴에 바로 이동 가능.
- 한 턴에 도착한 유닛은 그 턴에 다시 이동할 수 없다. 자리 맞바꾸기 이동은 양쪽 모두 정상 처리.

→ 결정되는 것: `decide`의 시간 예산. Python 기동·파싱·출력 여유를 빼고 **일반 턴 계산은
100~150 ms 이내**를 목표로 잡는 것을 제안(숫자는 제안이며 실측 후 조정). 15×15=225칸이라
BFS 전체 거리표는 싸다. 무거운 사전 계산은 첫 턴(3초)에 한다.

## 5. 상태 입력

원문 형식 (꺾쇠·화살표는 설명용):

```
INIT 15 15
TEAM Y
MAP ...............    ← 15줄
BUILDINGS 17
<id> <x> <y> <종류>    ← 17줄
BASE Y <x> <y>
BASE K <x> <y>
END
```

```
TURN <n>
RESOURCE <내 자원> <상대 자원>
UNITS <k>
<팀> <병종> <x> <y> <수>      ← k줄
BUILDINGS 17
<id> <x> <y> <종류> <소유> <단계> <점수>  ← 17줄
END
```

- **매 턴 전체 상태**가 온다 (차분 아님).
- `MAP` 문자: `.` 평지 · `#` 장애물 · `B` 건물 · `H` 본진. `BUILDINGS 17`에 본진 2개는 포함되지 않는다.
- `<종류>`: `PLAZA` `HALL` `STATION` `LIBRARY` `ENG` `HOSPITAL` `WATCH` `DEPOT`
- `<소유>`: `N` / `Y` / `K`. `<단계>`: 0(중립) · 1(직전 턴에 중립이 됨 — 판정상 0과 같음, 정보 표시) · 2(소유)
- `<점수>`: 모르면 `-1`. 음수 점수가 아니라 "모름".
- 정렬: UNITS는 (팀 Y→K, 병종 F→W→S, y, x), BUILDINGS는 id 오름차순.
- 우리/상대 구분: INIT의 `TEAM` 줄. RESOURCE는 (내, 상대) 순서.

입력 → `World` 이름 (`agent/world.py`에 구현됨, 2026-09-27):

| 입력 | 타입 | 의미 | `World`에서의 이름 | 쓰는 사람 |
| --- | --- | --- | --- | --- |
| `INIT w h` | int, int | 맵 크기 (항상 15×15) | `map.width`, `map.height` | 전원 |
| `TEAM` | `Y`/`K` | 우리 진영 | `me` | 전원 |
| `MAP` 15줄 | 문자 격자 | 지형 (경기 중 불변) | `map.rows[y][x]` / `map.passable(pos)` | 성혁 |
| INIT `BUILDINGS` | id, x, y, 종류 | 건물 고정 정보 | (매 턴 블록에 다시 오므로 버림) | – |
| `BASE Y/K` | x, y | 양 본진 위치 | `map.bases[team]` | 전원 |
| `TURN n` | int | 현재 턴 | `turn` | 현진 |
| `RESOURCE a b` | int, int | 내·상대 자원 | `gold[me]`, `gold[enemy]` | 현진 |
| `UNITS` 줄 | 팀, 병종, x, y, 수 | 셀별 인원 | `units[(team, kind, (x, y))] = n`, `units_of(team, kind)` | 전원 |
| 턴 `BUILDINGS` | id, x, y, 종류 | 건물 | `buildings[id].pos`, `.kind` | 전원 |
| 턴 `BUILDINGS` 소유 | `N`/`Y`/`K` | 소유자 | `buildings[id].owner` (중립은 `None`) | 현진 |
| 턴 `BUILDINGS` 단계 | 0/1/2 | 점령 단계 | `buildings[id].just_neutralized` (단계 1) | 현진 |
| 턴 `BUILDINGS` 점수 | int, -1=모름 | 건물 점수 | `buildings[id].score: int \| None` | 현진 |

입력에 없어서 **우리가 직접 추적해야 하는 것**:

- 대칭 짝 id (`map.mirror(pos)`)와 짝 점수 추론
- 우리·상대가 이미 받은 보급소 보너스 (팀별·건물별 1회)
- 이번 턴 TELE 사용 여부 (출력 쪽에서 관리)

→ 결정되는 것: `agent/world.py` **전체**, `agent/adapter.py`의 파싱.
→ 주의: `world.py`는 세 파일이 공유하는 계약입니다. 이 표가 바뀌면 셋 다에게 알립니다.

## 6. 맵 표현

- 형태: **격자**, 15×15.
- 좌표계: x = 열(0~14, 왼→오), y = 행(0~14, 위→아래). 입출력 모두 `x y` 순서.
- 이동: **4방향** U(y−1) D(y+1) L(x−1) R(x+1). 대기(제자리)는 명령을 안 내면 된다.
- 이동 비용: 모든 칸 동일. 깃발병·전투병 턴당 1칸, 정찰병 최대 2칸(MOVE2, 꺾기 가능, 경유 칸도
  통과 가능해야 함).
- 통과 불가: 장애물 `#`, 맵 밖. 유닛 겹침은 통과 가능(같은 팀 무제한 중첩, 적과 겹치면 전투).
- 건물 `B`·본진 `H`는 통과 가능. **상대 본진에 들어갈 수 있는지·그때 무슨 일이 있는지는 원문에 없음** — 11절.
- 맵은 경기 중 변하지 않는다. 시드마다 다른 맵(모의 전투도 매번 10개 서로 다른 맵).
- 맵은 (7,7) 기준 **180° 점대칭**. 장애물 10쌍(20칸). 모든 건물·본진은 서로 도달 가능.
  본진 간 맨해튼 거리 ≥ 12.
- 건물 17개: 중앙광장 1(정중앙 (7,7), 항상 3점) + 신촌 5 + 안암 5 (학생회관·도서관·공학관·병원·역)
  + 중앙 6 (서울역 2·방송국 2·보급소 2, y 2~12 범위).
- 텔레포트: 아군 역 2개 이상 보유 시 역↔역 순간이동(턴당 1회, 최대 5명). 역은 총 4곳
  (신촌역·안암역·서울역 2).
- 시야: 지형·유닛·자원·소유권은 전부 보인다. 안개 없음. 숨겨진 것은 **건물 점수뿐**(10절).

→ 결정되는 것: `agent/algorithms.py`는 **4방향 격자 BFS**로 충분(칸 비용이 같으므로 다익스트라/A\*
불필요). 225칸이라 매 턴 전체 거리표를 계산해도 된다. TELE는 역 사이 0거리 간선으로 확장 가능.

## 7. 행동

| 명령 | 형식 (토큰 수) | 제약 | 무시되는 경우 |
| --- | --- | --- | --- |
| SPAWN | `SPAWN <F/W/S> <수>` (3) 본진 / `SPAWN <F/W/S> <수> <x> <y>` (5) 병원 | 비용 F5 W3 S2. 공학관 1개당 W −1(최소 2) | 좌표가 내 병원이 아님, **본진 좌표를 명시함**, 인원 ≤ 0. 자원 부족이면 가능한 만큼만 생산 |
| MOVE | `MOVE <x> <y> <병종> <수> <U/D/L/R>` (6) | 1칸 | 도착 칸이 장애물·맵 밖. 인원 부족이면 가능한 만큼만 |
| MOVE2 | `MOVE2 <x> <y> S <수> <방향1> <방향2>` (7) | 정찰병 전용, 2칸 | 경유·도착 칸 중 하나라도 장애물·맵 밖이면 **명령 전체** 무효 |
| TELE | `TELE <x> <y> <병종> <수> <tx> <ty>` (7) | 출발·도착 모두 내 역, 내 역 ≥ 2개, 턴당 1회, 최대 5명, 병종 하나 | 첫 번째 유효 명령만 처리. 실제 이동 0명이면 횟수 소모 안 함 |
| PRIORITY | `PRIORITY x1 y1 x2 y2 ...` | 자원 부족 시 점령 순서. 마지막 줄만 유효 | 좌표 개수가 홀수면 줄 전체 무시 |
| END | `END` (1) | **필수** | 누락 시 몰수패 |

- 한 턴에 명령 개수 제한은 출력 한도(4,096줄)뿐. 셀·병종 단위로 인원을 나눠 여러 방향으로 보낼 수 있다.
- 형식 검증이 엄격하다: 토큰 수가 하나라도 다르면 그 줄 무시. 잘못된 줄은 그 줄만 무시(실격 아님).
- 처리 순서는 단계 순(생산 → 이동 → …), 같은 단계 안에서는 출력 순서.
- MOVE 인원은 "적용 시점의 잔여 인원" 기준. 같은 턴에 도착한 유닛은 다시 이동 불가.
- 점령 명령은 없다. 깃발병이 건물 위에 살아 있고 자원이 있으면 자동 진행.
- 성공/실패 응답은 없다. 다음 턴 상태로 확인해야 한다.

출력 예시:

```
SPAWN F 1
MOVE 2 12 F 1 U
PRIORITY 7 7 3 10
END
```

→ 결정되는 것: `agent/adapter.py`의 명령 직렬화, `agent/strategy.py`가 고를 수 있는 선택지.

### 전투 (원문 6장)

같은 셀에 양 팀 유닛이 있으면:

1. 전투병 수 상쇄 (적은 쪽 수만큼 양쪽에서 제거)
2. 전투병이 남은 팀이 있으면 상대 깃발병·정찰병 전원 제거
3. 양쪽 전투병 0이면 아무 일 없음

- 건물 위에 양 팀 깃발병이 함께 있으면 그 턴 그 건물 점령은 양쪽 모두 진행 안 됨(경합).
- 내 소유 건물 위의 내 깃발병이 전투로 죽으면 건물이 즉시 중립이 된다(깃발 뽑힘).

### 점령 (원문 7장)

- 중립 → 내 것: 비용 2 (광장 4), 즉시.
- 상대 것 → 중립 → 내 것: 2단계, 각 비용 2 (광장 4), 한 턴에 한 단계 → 최소 2턴.
- 단, 상대 수비 깃발병을 내 전투병이 전투에서 제거하면 건물은 전투 단계에서 중립이 되고, 살아남은
  내 깃발병이 **같은 턴에** 점령한다.
- 도서관 보유 시 단계당 −1 (최소 1, 중첩 없음). 깃발병 수와 무관하게 건물당 한 단계분 비용.
- 자원 부족 시 순서: PRIORITY → 점수 높은 순(모르는 점수는 0) → 자기 본진 기준 정규화 (y, x) 사전순.
- 깃발병이 떠나도 소유는 유지된다(전투로 뽑히는 경우만 제외).

## 8. 점수와 승패

- 점수: 내가 소유한 건물의 점수 합. 신촌·안암 건물 1~2점, 중앙 건물 2~4점, 광장 3점.
  대칭 짝은 같은 점수 → **맵 총점은 항상 홀수**.
- 즉시 승리: 상대 소유 건물 점수 합 = 0 **이고** 내 점수 > 맵 총점의 절반.
- 160턴 종료 시 판정 순서:
  1. 점령 점수 합
  2. 누적 점령-턴 (매 턴 점령 단계 직후 소유 건물 점수 합을 누적. 실제 점수 기준)
  3. 생존 병력 환산 (F 5, W 3, S 2)
  4. 모두 같으면 무승부
- 페널티: 없음. 단 시간 초과·비정상 종료·`END` 누락은 몰수패.
- 순위: 최종 평가는 반대 진영 전 팀과 1경기씩, **승점률**로 비교. 리더보드는 참고용.

→ 결정되는 것: `agent/strategy.py`의 우선순위. 2순위(누적 점령-턴) 때문에 **일찍 먹고 오래 지키는
것**이 동점 상황에서 유리하다는 점은 규칙에 명시되어 있다.

## 10. 불확실성 / 관측 제한

- 상대 유닛 위치·병종·인원, 상대 자원, 건물 소유권·단계: **전부 공개.**
- 유일한 비공개 정보: **건물 점수** (`-1`). 한 번 공개되면 영구. 공개 조건:
  - 내 유닛이 그 건물 칸에 있음 (병종 무관)
  - 내 정찰병에서 체비쇼프 거리 2 이내
  - 내가 소유한 방송국에서 체비쇼프 거리 3 이내
  - 판정은 정보 공개 단계에 **살아남은 유닛의 최종 위치** 기준(경유 칸·죽은 유닛은 공개 못 함)
- 공개는 팀별이다. 상대가 무엇을 아는지는 모른다.
- 대칭 짝 점수는 같다 → 한쪽을 알면 반대쪽도 안다(자동 공개되지 않으므로 직접 계산).
- 광장은 항상 3점. 맵 총점이 홀수라는 사실도 추론에 쓸 수 있다.
- 무작위 요소: 맵(시드). 같은 시드는 같은 맵. 경기 진행 자체에 무작위 판정은 원문에 없음.
- 동시 턴이므로 **상대의 이번 턴 행동은 모른다** — 추정해야 하는 것은 이것.

→ 결정되는 것: `World`에서 모르는 점수는 `None`으로 표현한다. `-1`을 그대로 두거나 `0`으로 바꾸지
않는다. 단, 게임 엔진의 기본 점령 순서는 모르는 점수를 0으로 취급한다는 점은 따로 기억할 것.

- `BALANCE`에 규칙서에 없는 값이 하나 있다: `regions = {sinchon: [0, 4], center: [5, 9], anam: [10, 14]}`.
  어느 축(x/y) 기준인지는 적혀 있지 않다.
- `search.directions()`는 본진 x좌표가 가운데보다 크면 방향 순서를 뒤집는다(자기 본진 기준 정규화).
