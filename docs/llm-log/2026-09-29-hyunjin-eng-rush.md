## 목적

- 흉내 봇 풀에서 가장 이기기 어려운 공학관 러시의 핵심 동작을 우리 봇에 더하면, 별동대가 그 공학관으로 가는 깃발병을
  지켜 주어 서로 돕는지 확인

## 범위 — LLM이 한 것

- `agent/strategy.py`(테마 브랜치): 상수 `ENG_RUSH_UNTIL`·`ENG_RUSH_EXTRA`·`ENG_RUSH_VALUE`·`ENG_RUSH_CAPTURE`, 과제 만들기
  함수 `eng_rush_tasks`(상대 본진이 더 가까운 공학관 중 우리 것이 아닌 곳에 전투병 "위협 + 2"명), `capture_tasks`에 러시 기간
  공학관 점령 가치 배수, 트리 잎 `eng_rush()`를 네 국면 가지의 별동대 다음에 추가, 모듈 설명 한 줄. 기본값 80턴
- 설정 8가지 대전과 80턴 확인 대전, `docs/benchmarks.md` 한 줄

## 검증

- `ruff check` 통과. 대조: 러시를 끈 값(0) vs 별동대 버전(`26fae2a`) `sim diff` → 10경기 1590턴 명령이 모두 같음
- 별동대 버전 상대 시드 200~299 200경기씩: 러시 20 / 40 / 60 / 80 / 100 / 160턴 → 53 / 55 / 63 / 65 / 65 / 60%,
  40턴에 추가 인원 0 → 48%, 40턴에 깃발병 점령 가치 ×1 → 53%
- 80턴: 별동대 버전 상대 시드 300~399 52% (45–59%, 두 묶음 합계 58.5%), `main` 상대 200~299 69% (별동대 버전도 69%),
  서버 맵 49개 71.4% (별동대 버전 67.3%), `moonwon/eval-tuning` 상대 49% (별동대 버전 50%), 흉내 봇 풀
  60 / 68 / 88 / 60% (평균 69%, 별동대 버전 62%)
- 응답 시간: 여러 대전을 동시에 돌린 묶음에서 최대 76~115 ms가 나왔으나 서버 맵 대전을 단독으로 다시 돌리면 우리 20 ms,
  `main` 27 ms → PC 부하로 판단
- 결론: 두 번째 시드 묶음에서는 차이가 작지만, 합계·흉내 봇 풀·서버 맵이 모두 좋아지고 나빠진 지표가 없어 80턴으로 켰다
