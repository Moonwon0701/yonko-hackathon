## 범위 — LLM이 한 것

- 질문 1에 대한 분석: 한 턴에 여러 명령을 내는 배분 문제라 BT 단독보다 BT(국면 선택) + 효용
  점수(목표 배정) 혼합을 권함. 가중치를 `.py`에 상수로 넣는 것은 규정 문구상 금지 대상이고
  우회 시도는 실격 사유라고 판단. 채널톡 문의 문안 작성
- `CLAUDE.md`: RL 문단을 "전략 방식: 규칙 기반" 절로 교체, "LLM 사용 기록" 절 추가, PR 본문
  형식에 "LLM 사용" 항목 추가
- `README.md`: 담당 표와 RL 안내를 규칙 기반으로 수정, 문서 목록에 LLM 기록 폴더 추가
- `docs/llm-log/README.md`: 기록 틀과 사용법
- `docs/llm-log/2026-09-27-*.md`: 오늘 앞선 작업(PR #14·#15·#16) 기록을 이 대화의 프롬프트
  원문으로 소급 작성
- 제안 수정: 기록 대상을 "코드 수정"에서 "저장소 파일(코드·문서) 수정"으로 넓힘. 규칙 문서처럼
  LLM이 쓴 문서도 보고서 기재 대상이기 때문
