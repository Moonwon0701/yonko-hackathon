## 목적

- `agent/strategy.py`의 상수들을 사람이 하나씩 실험하던 것을, 상대 풀(흉내 봇 + 기준 봇 자신)에 대한 승점률로
  자동으로 고른다. 잡음으로 뽑힌 값을 거르는 절차를 넣고, 모든 평가를 기록해 보고서의 정량 근거로 쓴다.

## 범위 — LLM이 한 것

- `scripts/tune.py`: 좌표 탐색. 기준 커밋의 봇에 상수를 덮어쓰는 런처 파일을 설정마다 만들고, 상대 풀과 학습 시드로
  승점을 잰다. 상수마다 격자의 다른 값을 모두 두고, 가장 좋은 값이 학습 시드에서 +2%p 이상이면서 검증 시드(다른
  맵)에서도 지금보다 좋을 때만 채택한다. `--check`는 설정 하나를 기준과 비교한다. 기록은 `runs/tune/<시각>/log.jsonl`.
- 탐색 대상 상수 19개를 고를 때 `strategy.py`에서 각 상수가 쓰이는 곳을 확인했다. `DANGER_DISCOUNT`·`HOLD_TURNS`는
  모듈을 불러올 때 행동 트리에 값이 박혀 덮어써도 효과가 없어 뺐다.

- 탐색 실행(`--seeds 40 --rounds 2`)과 결과 확인: 채택 `MIN_FLAGS` 2 → 3 하나. 새 시드 3000~3049와 서버 맵 49개에서
  다시 재어, 흉내 봇에는 강해지지만 `main`과 직접 대결은 42.9%라 `main`에 넣지 않는다고 판단해 `docs/benchmarks.md`에
  "파라미터 탐색" 절을 새로 만들어 적었다.
- 프롬프트 2: 문원이 추가한 `data/server-replays/2026-09-28_not_faced/`(크아앙 팀 시점 5판)를 `profile_opponents`의 함수로
  양쪽 모두 재고, Team 24전은 턴별로 봤다. 결과(Team 24는 뭉쳐서 상대 진영에서 싸우는 다른 강팀 모습, 수비 배치가 높은
  크아앙은 29위)를 `docs/benchmarks.md` "서버 리더보드" 표에 한 줄로 더했다. 리플레이 파일 자체는 커밋하지 않았다.

## 사람이 한 것

- 문원: 흉내 봇 보강보다 자동 탐색을 먼저 하기로 정했다. 크아앙 팀에게서 우리가 안 만난 5팀 상대 리플레이를 받아 넣었다.

## 검증

- 기준 봇끼리 50.0%(대칭), 평가 한 번(160경기) 약 6초.
- `MIN_FLAGS=3`: 새 시드 50개 풀 평균 46.0 → 51.0%, 서버 맵 49개 `main` 상대 42.9% (34–53%).
