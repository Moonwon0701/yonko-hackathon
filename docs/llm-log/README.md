# LLM 사용 기록

대회 규정(운영 규칙 4장)상 LLM을 쓰면 보고서에 아래 세 가지를 반드시 적어야 합니다.
빠뜨리면 감점 또는 실격 대상입니다.

- 사용한 LLM의 모델 정보
- 입력한 프롬프트
- 사용 목적과 범위 (어느 부분에 어떻게 활용했는지)

이 폴더가 그 원자료입니다. 규칙은 [CLAUDE.md](../../CLAUDE.md)의 "LLM 사용 기록" 절에 있습니다.
요약하면 **Claude Code가 저장소 파일을 고치면, 그 PR에 기록 파일 하나를 같이 넣습니다.**

## 파일 이름

`YYYY-MM-DD-이름-주제.md` — 예: `2026-09-27-moonwon-port-starter.md`

작업(PR) 하나당 파일 하나입니다. 한 파일에 계속 덧붙이면 셋이 동시에 쓸 때 충돌이 납니다.

## 틀

```markdown
# <작업 한 줄 요약>

- 날짜: 2026-09-27
- 요청한 사람: 문원
- 모델: Claude Opus 5.5 (`claude-opus-5-5`), Claude Code CLI
- PR: #16 (브랜치 `moonwon/port-starter`)

## 프롬프트 (원문 그대로)

1. > 사용자가 입력한 문장 그대로
2. > 이어서 입력한 문장

## 목적

- 왜 LLM을 썼는가

## 범위 — LLM이 한 것

- 만들거나 고친 파일과, 각 파일에서 한 일

## 사람이 한 것

- 사람이 내린 판단, 직접 고친 부분, 확인·머지

## 검증

- 결과를 어떻게 확인했는가 (테스트, 실측 수치)
```

## 보고서 쓸 때

이 폴더의 파일을 날짜순으로 읽으면 "개발 과정"(30점)의 흐름이 됩니다. "무엇을 문제로 보았고,
어떤 근거로 바꾸었고, 어떻게 확인했는가"가 목적·범위·검증 칸에 해당합니다.

파일을 고치지 않은 상담(전략 질문 등)은 자동으로 기록되지 않습니다. 보고서에 넣어야 할 만큼
결정에 영향을 줬다면 그 자리에서 "이것도 LLM 기록에 남겨 줘"라고 요청하세요.
