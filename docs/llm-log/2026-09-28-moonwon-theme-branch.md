## 프롬프트 (원문 그대로)

1. > 이제 우리도 협업 규칙에 따라서 작업하자.
2. > 우선 자체 전략 개발부터 하자
3. (LLM이 "무엇부터 다룰까요? 중반 중앙 싸움 / 우위에서 마무리 못 함 / 둘 다" 선택지를 내자 직접 입력)
   > 내 자체 전략 개발도 다른 브랜치에서 해야해
4. (LLM이 "문원 테마 브랜치 / 기능 브랜치 → PR" 선택지와 주제 선택지를 다시 내자)
   > 문원 테마 브랜치

   > 1번은 전략의 결과라 애매하고, 2번은 어차피 승리로 이어지게 되어있어. 다른 개선 테마를 찾아보자
5. (LLM이 "평가·튜닝 / 상대 행동 예측 / 정보·점수 추론" 선택지를 내자) "평가·튜닝 (Recommended)" 선택

## 목적

- 문원도 성혁·현진처럼 테마 브랜치에서 자체 개발을 하기로 해서, 협업 표와 규칙 문서를 그에 맞게 고친다.
- 문원 테마를 정할 근거(지금까지의 실험 기록과 리더보드 분석)를 정리한다.

## 범위 — LLM이 한 것

- 프롬프트 1: `git fetch`로 테마 브랜치 상태를 확인했다(성혁 새 커밋 없음, 현진 실험 브랜치 3개 모두 "안 씀" 기록).
  머지된 로컬 브랜치 `moonwon/setup-fixes`·`moonwon/collab-plan`과 그 worktree를 정리했다(파일 수정 없음).
- 프롬프트 2~3: `docs/benchmarks.md`와 `agent/strategy.py`를 읽고 9/28 22:00 리더보드 분석에서 약점 두 가지
  (20~35턴 중앙 싸움, 압도적 우위에서 구석 건물 마무리 실패)를 주제 후보로 냈다. 문원 브랜치 방식이 CLAUDE.md
  협업 표(문원 = `main`)와 어긋나는지 확인하는 질문을 했다.
- 프롬프트 4: 공격·확장(성혁)·수비·자원(현진)과 겹치지 않는 테마 후보 셋을 냈다.
  - 평가·튜닝(추천): 로컬 상대가 우리 옛 버전과 스타터 봇뿐(`sim/bots.py`)이라 실험 결과가 가위바위보·오차 안인
    경우가 많았고, 로컬 우위가 9/28 22:00 리더보드 19위로 이어지지 않았다는 근거
  - 상대 행동 예측: 위협 맵이 최악 가정이라 깃발병이 지나치게 조심한다는 근거
  - 정보·점수 추론: 유일한 숨은 정보인 건물 점수를 더 빨리 알아내는 방향(강팀도 정찰병을 안 써서 효과는 작을 수 있음)
- 프롬프트 5: 문서를 고쳤다.
  - `CLAUDE.md`: 협업 표의 문원 줄을 `moonwon/eval-tuning` + `main` 통합, 테마 **평가·튜닝**으로 바꾸고, 문원도 자체
    개발은 테마 브랜치에서 한다는 규칙을 더했다. "전략 방식" 절의 "`main`의 전략 코드·파라미터 튜닝은 문원"을
    "문원 테마 브랜치에서 개발해 `main`으로 옮긴다"로 바꿨다.
  - `README.md`: 협업 표의 문원 줄을 같은 내용으로 바꾸고 한 줄 설명을 더했다.

## 사람이 한 것

- 문원: 자체 개발도 `main`이 아닌 별도 테마 브랜치에서 하기로 정했다. LLM이 낸 첫 주제 후보 둘(중반 중앙 싸움 =
  전략의 결과라 테마로 애매함, 우위 마무리 = 어차피 승리로 이어짐)을 받아들이지 않고 다른 테마를 요구했다.
  평가·튜닝 테마를 골랐다.

## 검증

- 문서만 고쳤으므로 코드 테스트는 돌리지 않았다.
