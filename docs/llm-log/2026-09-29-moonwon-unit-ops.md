# 유닛 운용 분석과 실험 스위치 (모아서 들어가기·요격·비용 교환·1명 과제)

- 날짜: 2026-09-29
- 요청한 사람: 문원
- 모델: Claude Opus 5.5 (`claude-opus-5-5`), Claude Code CLI
- PR: 없음 (실험 브랜치 `moonwon/unit-ops`, `moonwon/merge-squad` `6bb20e4`에서 시작)

## 프롬프트 (원문 그대로)

1. > 다른 브랜치에서 현진 + 내 자체 개발 머지 진행하고 있어. 다른 아이디어 더 내보자. 유닛 운용 측면에서 고민해봐도 될 것 같아
2. > 전부다 실험해봐
3. > 얼마나 걸려
4. > 배터리가 없어. 일단 실험 종료해줘

## 목적

- 서버 리플레이에서 유닛 운용의 약점을 찾고, 그 결과로 낸 아이디어 4개를 스위치로 넣어 시험한다

## 범위 — LLM이 한 것

- 분석(일회용 스크립트, 저장소에 넣지 않음): 서버 리플레이 48판 10~80턴 전투 6155건을 우리 명령 줄로 전투 전 인원을 복원
  - 전투의 36%에 우리가 전투병 1명으로 들어가 승 8%(6명 이상 71%). 상대가 먼저 있던 칸에 들어간 전투 55% 패(2.6 : 7.5),
    진 전투의 약 절반은 직전 턴 2칸 안에 우리 전투병이 더 있었음. 로컬(현진 봇 상대 50경기)도 1명 전투 42%, 승 2%
  - 우리 건물이 중립이 된 경로(1~80턴 경기당): 상대 깃발병의 중립화 9~12회, 건물 위 깃발병 전사 2회
- `agent/strategy.py`에 스위치(모두 기본 끔): `STAGE`(1 = 적 전투병이 선 과제 칸 앞에서 전원 도착까지 대기, 2 = 1 + 적이 더
  많은 칸에 안 들어감), `INTERCEPT_IDLE`·`INTERCEPT_VALUE`·`INTERCEPT_RADIUS`(적 깃발병의 예상 목적지 건물로 먼저 감),
  `TRADE_BOOST`·`TRADE_KINDS`(전투병 값이 싸면 공격 과제 가치를 올리고 비싸면 내림), `PICKET_NEED`·`ESCORT_NEED`

## 사람이 한 것

- 유닛 운용 쪽 아이디어를 요청하고, 네 가지를 모두 실험하기로 결정
- 배터리 문제로 평가를 중간에 멈추기로 결정

## 검증

- 기본값(끔)에서 `sim diff` 20경기 3200턴 명령이 모두 같음. `pytest` 831개 통과
- 끝난 결과(나머지는 멈춤으로 못 돌림)
  - `tune.py --check "STAGE=1" --seeds 50 --seed 3000`: 기준 71.5% → 41.6% (기준 봇 상대 24%, `eng_rush` 34%, `econ_raid` 40%,
    `wide` 80%, `blob` 30%)
  - 현진 봇(`hyunjin/defense-econ`) 상대 시드 7000~7014(30경기): 끔 → `STAGE=2`: 전투 승률 37 → 47%, 1명 전투 37 → 31%,
    경기 승률 50 → 30%. 칸은 더 따내지만 기다리는 동안 깃발병·건물을 놓친다
- 못 돌린 설정: `STAGE=2`(풀), `INTERCEPT_IDLE=1`, `INTERCEPT_VALUE=1.0`, 둘 다, `TRADE_BOOST=1.5`·`2.0`, `PICKET_NEED=2`,
  `PICKET_VALUE=0`, `ESCORT_NEED=2`, `FRONT_NEED=2`
