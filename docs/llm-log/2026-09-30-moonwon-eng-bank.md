## 목적

- 병력 배치·수비 스위치가 모두 제출본을 넘지 못해, 규칙에서 아직 쓰지 않는 이득을 찾는다

## 범위 — LLM이 한 것

- 후보 다섯 개를 정리(공학관 타이밍 생산, 값 차이 교전, 경기 중 상대 스타일 감지, 막판 몰아 쓰기, 봇 안 모의 굴리기)하고,
  병력 배치를 건드리지 않는 공학관 타이밍 생산을 먼저 고름
- 리플레이 분석(일회용 스크립트): 60판에서 공학관을 얻기 1~2턴 전에 값 3으로 산 전투병 자원을 셈(판당 약 30)
  - 메인 작업 폴더가 다른 세션에서 `moonwon/eval-tuning`으로 바뀌어 있어, `main`의 리플레이는 `git archive`로 임시 폴더에 꺼내 씀
- `agent/strategy.py`: `ENG_BANK`(`produce`에서 전투병 생산을 줄임, `eng_coming`), `plan_flags`가 깃발병 1차 배정을 `t.flag_plan1`에 남김,
  `ENG_COST_FLOOR`·`RESOURCE_CAP` import. 처음엔 기본 끔으로 넣고, 검증 뒤 **기본값 2**로 켬
- 평가: 제출본과 직접(새 맵 두 묶음, 서버 맵) + 흉내 봇 풀 + 팀원 봇(현진 `7b8b67e`, `0f689cd`) 상대 → `docs/benchmarks.md`에 한 줄
- CPU가 100%인 원인을 확인: 다른 세션의 `scripts/es_train.py`(진화 전략 학습). 멈추지 않음

## 사람이 한 것

- 스위치 튜닝이 막히자 더 넓고 창의적인 구조 변경을 찾도록 방향을 바꿈

## 검증

- 기본 끔일 때 `sim diff` 10시드 20경기 3,200턴 명령이 직전 커밋과 같음. 기본값 2로 켠 뒤 `pytest tests` 833개 통과
- 적립 2: 제출본과 직접 새 맵 72.8%(8000번대) · 65.0%(9000번대), 서버 맵 64.8%, 풀 76.6 → 80.6%(5000번대) · 77.2%(9000번대).
  현진 상대 74.0 / 73.8%, `0f689cd` 상대 73.5 / 72.1%(제출본은 69.0 / 68.5, 69.5 / 71.2). 몰수 0
- 응답 시간: 같은 대결의 A(적립)·B(제출본) 최대 응답이 같음(97 · 72 ms). 다른 세션의 학습으로 CPU가 100%라 부하 없는 측정은 아직 안 함
