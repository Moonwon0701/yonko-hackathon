# 건물 점수 가중치를 턴에 따라 바꿈 (초반 약하게 → 후반 강하게)

- 날짜: 2026-10-01
- 요청한 사람: 문원
- 모델: Claude Opus 5.5 (`claude-opus-5-5`), Claude Code CLI
- PR: 없음 (테마 브랜치 `moonwon/eval-tuning`)

## 프롬프트 (원문 그대로)

1. > 건물 점수  가중치 초반엔 좀 약화 시켜서 경제 건물들 같은 기능이 있는 건물들 먼저 먹기/ 후반에는 점수가 좀 더 중요하니까 건물 점수 가중치 강화

## 목적

- 건물 가치 = 추정 점수 + 기능 가치에서, 점수 쪽 비중을 턴에 따라 바꿔 초반엔 학생회관·공학관 같은 기능 건물을 먼저 잡고,
  점수가 160턴 순간에만 세지는 후반엔 점수를 더 중시하게 한다.

## 범위 — LLM이 한 것

- `agent/strategy.py`: 상수 `SCORE_WEIGHT_EARLY`·`SCORE_WEIGHT_LATE`·`SCORE_RAMP_START`(20)·`SCORE_RAMP_END`(120)와 함수
  `score_weight(turn)`을 추가하고, `building_value`의 추정 점수에 곱함. 기능 가치·막판 점령/수비(`estimated_score` 직접 사용)는 그대로.
  구간·후보 값(0.5→1.5 등)은 LLM이 정함.
- 설정 5개를 새 랜덤 시드 맵으로 현재 봇(`074803e`)과 대결시키고, 좋은 두 설정을 다른 묶음·다른 상대(`337ab49`·`strong_wide`)로
  다시 잼. 0.5→1.5를 기본값으로 켬.
- `docs/benchmarks.md` "예측·스타일 감지·값 차이 교전" 표에 결과 한 줄, 이 기록 파일.

## 사람이 한 것

- 초반엔 기능 건물, 후반엔 점수를 중시한다는 방향을 정함.

## 검증

- 기본값 1.0/1.0일 때 `074803e`와 22판 전부 무승부(예전과 행동 동일).
- 0.5→1.5, 새 시드 31000·33000·35000번대 1,200판씩: 대 `074803e` 51.6%, 대 `337ab49` 53.5 → 59.5%, 대 `strong_wide` 76.3 → 80.5%.
  나머지 설정(0.5→1.0, 1.0→1.5, 0.3→2.0, 0.7→1.3, 0.5→2.0)은 흔들림 안. 표는 `docs/benchmarks.md`.
- 새 기본값 봇 대 0.5→1.5 설정 40판 전부 무승부.
- `pytest tests` 855개 통과, 2개 실패는 `test_sim_match.py::test_misbehaving_bot_forfeits`(우리 봇을 쓰지 않는 시간 제한 테스트).
  변경 전 코드로도 세 번 돌려 1~4개씩 실패해 이 변경과 무관한 이 PC의 시간 흔들림으로 판단.
