- 날짜: 2026-09-29
- 요청한 사람: 문원
- 모델: Claude Opus 5.5 (`claude-opus-5-5`), Claude Code CLI
- PR: 없음 (테마 브랜치 `moonwon/eval-tuning`)

## 프롬프트 (원문 그대로)

1. (LLM이 유닛 운용 분석 결과와 "경제 건물 쟁탈 + 넓게 깔기·수비 배치·깃발병 호위"를 흉내 봇에 얹자는 제안을 내자)
   > 그 방향으로 흉내 봇 만들어 보자. 깃발병 호위가 부족하고 깃발병이 자주 죽는다는 통계는 이슈로 남겨둬도 괜찮을 것 같아

## 목적

- 로컬 상대가 우리 옛 버전과 스타터뿐이라 서버 강팀에게 지는 모습을 로컬에서 볼 수 없었다. 강팀의 운용을 흉내 낸
  상대 풀을 만들어, 전략 수정과 파라미터 탐색을 서버와 비슷한 조건에서 평가한다.

## 범위 — LLM이 한 것

- GitHub 이슈 #50 "깃발병 호위가 부족하고 깃발병이 자주 죽는다"를 만들었다(분석 수치, 다시 보는 명령, 한계, 손볼 곳 후보).
- `opponents/base/`: `main` `8fd93ee`의 `main.py`·`agent/`를 `git archive`로 복사해 고정했다. 우리 전략을 고쳐도 흉내 봇은
  바뀌지 않는다. `pyproject.toml`에서 ruff 대상에서 뺐다.
- `opponents/mimic.py`: 기준 봇 위에 과제를 더하는 부품(`add_tasks`, `scale_capture`, `escort_flags`, `garrison`,
  `pickets`, `enemy_campus`). 기준 봇의 `Turn.tasks`를 감싸는 방식이라 기준 봇 코드는 고치지 않는다.
- 흉내 봇 3개: `eng_rush.py`(참새튀김기·페이커: 40턴까지 상대 캠퍼스 공학관에 전투병 + 깃발병), `econ_raid.py`(AIKU:
  30턴부터 상대 공학관·학생회관·병원 급습), `wide.py`(모든상금: 깃발병 3명, 모든 비소유 건물에 초소). 모두 깃발병 호위와
  초소를 켠다.
- `scripts/profile_opponents.py`에 `from_local`(로컬 경기 기록 → 서버 리플레이 형식)을 더하고, 분석 함수가 경기 dict도
  받게 했다.
- `scripts/eval_pool.py`: 봇 A를 상대 풀과 여러 시드로 붙여 승점률과 서버 분석과 같은 지표(생산량, 전투병 값 3 비율,
  공학관 잃음, 10~30턴 운용)를 상대마다 한 줄로 낸다.
- 설정 비교: 처음 버전(우리 건물 전부 수비 배치)은 수비 배치가 82~88%로 서버 강팀(43%)과 달라, 공학관 러시 위에서
  수비 배치·초소 조합 5가지와 초소 가치·호위 가치 4가지를 비교했다. "수비 배치 없이 상대 건물 초소"가 서버와 가장
  가까워(45%) 세 봇에 적용했다. 상대 진영 전투 비율(32~38% vs 서버 50%)은 설정으로 움직이지 않아, 과적합을 피하려고 멈췄다.
- `docs/benchmarks.md`에 "상대 풀 (흉내 봇)" 절을 새로 만들었다(기존 표 끝은 충돌이 잦아서).

## 사람이 한 것

  남기기로 정했다.
