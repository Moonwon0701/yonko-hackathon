## 목적

- 서버 모의 전투 리플레이에서 응답 시간이 최대 214 ms(제한 300 ms)이고 우리 유닛 수에 비례해 늘어나는 것을
  발견. 160턴까지 가는 경기에서 몰수패가 날 수 있어 고치기 위해

## 범위 — LLM이 한 것

- 1·3번: 서버 리플레이 형식 분석, 중복 파일 2개 발견(고유 경기 19개, 고유 맵 10개), 승패·응답 시간 집계.
  리플레이 관측 상태를 INIT/TURN 텍스트로 바꿔 우리 decide에 넣는 스크래치 스크립트로 서버 응답 ≈ 10 + 12 × 로컬
  계산 시간(상관 0.73)임을 확인
- 2번: 전투병 상한 대신 원인을 프로파일로 찾음 — 시간의 89%가 과제 없는 전투병 한 명마다 도는 BFS(`first_step`).
  NumPy는 반복 횟수 문제라 효과가 적다고 판단해 쓰지 않음
- `agent/strategy.py`(현진 담당):
  - 과제 없는 전투병은 공통 목표에서 다중 출발 BFS 한 번(`distance_map`) + 칸별로 묶어 `step_along`
  - 거리표 캐시를 턴을 넘어 유지 (맵이 바뀌면 비움)
- `tests/test_strategy.py`: 성능 회귀 테스트. 처음 쓴 판이 수정 전 코드에서도 통과하는 것을 발견해, 수정 전
  코드가 느려지는 배치(목표가 먼 전투병 224명)로 바꾸고 수정 전 코드에서 실패하는 것을 확인
- `docs/benchmarks.md`: 응답 시간 절 신설

## 사람이 한 것

- 서버 모의 전투 리플레이 다운로드(중·상 봇), 전투병 상한은 성능을 제한한다는 판단, NumPy 대안 제시
