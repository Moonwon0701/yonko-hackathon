## 목적

- 깃발병 배정(탐욕)이 최적과 얼마나 다른지 재고, 최적 배정으로 바꿨을 때 효과를 확인해 담당자(성혁)에게 제안

## 범위 — LLM이 한 것

- 설명(1~3번, 파일 변경 없음): 헝가리안 방식, 지금 깃발병·전투병 배정의 형태, `ETA_OFFSET`(+2)은 0 나누기 방지가
  아니라 거리와 가치의 비중을 정하는 조절값이며 아직 튜닝하지 않았다는 것(남은 점령 단계가 1 이상이라 분모는 0이
  되지 않는다)
- 측정(4번): 서버 리플레이 매 턴 상태를 판단 트리에 넣고 `assign_flags` 입력을 가로채 탐욕 대 최적 효용 합 비교.
  임시 폴더에 헝가리안을 넣은 복사본으로 아레나 비교
- 속도(5번): 순수 Python과 NumPy 구현 비교(NumPy가 이 크기에선 더 느림). 아레나에서 보인 33 ms는 동시 24경기의
  CPU 경합이었고(동시 6경기에선 10 ms), 배정 자체는 최대 0.5 ms임을 확인
- 6번: 이전 수정(#42)과 분리해 `main`에서 새 브랜치로 구현
  - `agent/algorithms.py`: `max_assignment` 추가 (성혁 담당 파일 — 이 PR은 성혁이 확인 후 머지)
  - `agent/strategy.py` `assign_flags`: `max_assignment`로 1:1 짝을 고르고, 남는 깃발병은 각자 효용이 가장 높은
    과제로 겹쳐 보냄(예전과 같음)
  - `tests/test_strategy.py`: 테스트 3개(`max_assignment` 2개, 탐욕이면 틀리는 배정 1개 — 탐욕 코드에서 실패 확인)
  - `docs/benchmarks.md`: 측정 3줄

## 사람이 한 것

- 헝가리안 배정을 검토 대상으로 제안(1번)
- 파라미터 튜닝(ETA_OFFSET 등)은 BT가 성숙한 뒤로 미루기로 결정(4번)
- NumPy 구현의 속도 이득을 확인하도록 요청(5번)

## 검증

- `max_assignment`: 무작위 500문제에서 전수 탐색과 같은 효용 합
- `tests/test_strategy.py` 24개 통과 (자기 대전 대칭 테스트 포함)
- 서버 리플레이 40경기 매 턴 상태: 선택지가 있는 배정 중 최적과 다른 비율 28.1%(1차)·31.0%(2차), 효용 합 손실 0.56%·0.58%
- 로컬 아레나(`main` = `6570191` 상대, 각 200경기): 시드 0~99 60%, 100~199 48%, 서버 맵 67.9%, M4 79% (`main` 71%),
  M3 90% (`main` 92%), lv2 전승, 최대 응답 17 ms
- 결과가 섞여 있다(시드 100~199와 M3에서 조금 낮음). 효용 합이 커지는 것이 실제 게임 가치와 같지 않을 수 있다
