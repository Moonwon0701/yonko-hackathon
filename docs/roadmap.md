## 전략 구조: 지금과 목표

**M2까지: 효용 AI + 고정 순서.** `decide`는 매 턴 같은 순서로 한 번씩 실행된다. "지금 무엇을 할까"를
고르는 단계가 없어 늘 "확장"만 한다. 판단은 건물 효용 점수가 맡고, 전투병은 lv2에서 가져온 고정 규칙이다.

```
1. 목표 건물 고르기 → 효용 점수 매기기
2. 깃발병 배정 (효용 큰 짝부터)        ← 효용 기반
3. 점령 비용 예약 → 생산
4. 깃발병 이동 + PRIORITY
5. 전투병 이동 (적 깃발병 추격)         ← 고정 규칙
```

**M3부터: BT 위층 + 효용 아래층.** 위층이 국면을 고르고, 각 국면은 아래층 효용 배정기를 가중치만
바꿔 다시 쓴다(예: 굳히기 = 우리 건물 방어 가치 ↑, 공격 = 상대 건물 가치 ↑).

```
Selector (위에서부터 처음 성립하는 가지 실행)
├─ [본진·건물이 위협받나?] → 위협 대응
├─ [점수 앞서고 후반인가?] → 굳히기
├─ [약한 적 건물이 있나?]  → 공격
└─ 확장  ← 지금 decide가 하는 일은 사실상 이 가지 하나
```

아래층(M1·M2)을 먼저 만드는 이유: BT는 "언제 무엇을 할지"를 정하는 틀일 뿐, 실제로 유닛을 움직이는
부품은 아래층이다. 부품이 있어야 BT 가지가 호출할 것이 생긴다.

## M1. 목표 분산 + 건물 가치

- 건물 가치 = 추정 점수(모르면 진영 1.5 / 중앙 3.0, 대칭 짝·광장으로 추론) + 기능 가치(학생회관·보급소 등)
- 효용 = 가치 / (거리 + 점령 단계 + 2). 깃발병 한 명씩 탐욕 배정, **한 건물에 한 명**
- 점령 비용은 이번 턴 수입으로 못 메우는 만큼만 예약, 남는 자원은 전투병
- 동시 점령 2곳 이상이면 `PRIORITY`
- 결과(로컬): lv2 상대 100승. 목표 분산만으로 86승, 남는 자원 → 전투병이 나머지를 뒤집음

## M2. 위험 판단 + 깃발 뽑기

구현 요약 (`agent/strategy.py`):
- `threat_map`: 적 전투병 무리가 제자리·한 칸으로 모일 수 있는 최대 인원 + 이번 턴 적 본진 생산 가능분
- 전투병 과제(`warrior_tasks`): 적 깃발병 처치(건물 위면 그 건물 가치 추가 — 방어·점령 저지·깃발 뽑기),
  점령 중인 우리 깃발병 호위. 과제마다 필요 인원(적 위협 + 1, 호위는 같은 수)을 채울 수 있는 것 중
  가치 / (1 + 가장 먼 전투병 거리)가 큰 것부터 배정. 남는 전투병은 lv2처럼 적 깃발병 추격
- 깃발병(`flag_step`): 이동 뒤 칸의 적 위협 ≤ 우리 전투병이어야 들어간다. 아니면 대기 → 피하기
- 깃발 뽑기: 전투병 과제가 잡힌 적 깃발병 건물만 깃발병 목표가 되고, 전투병이 이번 턴 도착하지 못하면
  깃발병은 한 칸 앞에서 기다린다
- 전투병 수: 적 전투병 + 1 (최소 3)
- 동점 처리를 자기 본진 기준 정규화 좌표로 맞춰 자체 대전이 점대칭이 되게 함. 캠퍼스 역 판별도
  "본진에서 가장 가까운 역" → "본진 쪽으로 가장 치우친 역"으로 고침(중앙 서울역을 잘못 고르던 맵이 있었음)

- **algorithms:** 영향력 맵 `threat_map` — 다음 턴 적 전투병이 닿을 수 있는 칸과 그 인원 수
- 깃발병은 적 전투병이 더 많이 닿을 수 있는 칸으로 들어가지 않는다 (경로 비용에 위험 반영)
- 전투병 역할 분담: **요격**(우리 건물을 노리는 적 깃발병) · **호위**(점령 중인 우리 깃발병) · **공격**(깃발 뽑기)
- 전투병 상한 3을 없애고 적 전투병 수에 비례해 목표 인원을 정한다

### 핵심 전술: 깃발 뽑기 (문원 아이디어, 원문 6장·7장)

상대 소유 건물 위의 수비 깃발병을 전투로 제거하면 그 건물은 **전투 단계에서 즉시 중립**이 되고, 같은 칸에
내 깃발병이 살아 있으면 점령 단계에서 바로 내 소유가 된다 (`rules-original.md` 289·312줄).

| | 일반 점령 (중립화 → 점령) | 깃발 뽑기 (전투병 + 깃발병) |
| --- | --- | --- |
| 내 자원 | 2+2 = 4 (광장 8) | 2 (광장 4) |
| 걸리는 턴 | 최소 2턴 | 1턴 |
| 상대 손실 | 건물만 | 건물 + 깃발병(5) + 그 건물에 쓴 점령 비용 |
| 누적 점령-턴 | 상대가 1턴 더 쌓음 | 즉시 끊김 |

- 조건: 그 칸에서 내 전투병 수 > 상대 전투병 수
  - 수비 깃발병이 있으면 깃발병만 들어가도 **경합**이라 점령이 안 된다. 이 경우 전투병은 필수다
  - 빈 건물은 뽑을 깃발이 없으므로 일반 2단계로만 뺏을 수 있다
- 전투병만 보내도 깃발은 뽑힌다(중립화, 내 비용 0). 깃발병은 다음 턴에 2로 점령
- 동시 턴이라 상대 깃발병이 그 턴에 떠날 수 있다. 전투병과 깃발병이 **같은 턴에 도착**하도록 깃발병은 한 칸 앞에서 대기
- 효용 반영: 수비 깃발병이 있고 적 전투병이 약한 상대 건물은 비용·턴 절감 + 처치 보너스만큼 가치를 올린다
- **방어(역방향):** 점령을 마친 우리 깃발병이 건물 위에 머물면 뽑힐 표적이 된다. 소유는 떠나도 유지되므로
  적 전투병이 닿을 수 있으면 비킨다. 2턴 걸리는 상대 건물 공략 중에는 전투병 호위를 붙인다
- 효과는 상대 봇이 건물 위에 깃발병을 남기는 빈도에 달려 있다 → 모의 전투 기록에서 확인

## M3. BT 국면 선택

구현 요약 (`agent/strategy.py`):
- 국면 = 아래층 가중치 묶음 `Profile`(지키기 배수, 빼앗기 배수, 위험 회피 배수, 추가 전투병 수)
- 조건: 위협 대응 = 적 깃발병이 3칸 안에 들어온 우리 건물의 점수 합 ≥ 2 / 굳히기 = 110턴 이후 추정 점수
  우세 / 공격 = 우리 전투병 ≥ 적 + 2이고 상대가 건물 보유 / 확장 = 그 밖
- `select_phase`: 더 급한 국면은 바로, 덜 급한 국면은 지금 조건이 3턴 연속 풀린 뒤에만
- 새 전투병 과제 "지키기": 적 깃발병이 3칸 안에 있는 우리 건물 위에 전투병을 세운다 (M2 리플레이에서 같은
  건물을 빼앗고 뺏기기를 반복하던 문제)
- stderr 턴 로그에 국면: `#t 12 0.4ms THREAT MOVE4 SPAWN1`

### 구조 정리: 상태 머신 → 행동 트리 (9/27)

M3의 국면 선택은 이름은 BT였지만 실제로는 **히스테리시스가 있는 우선순위 상태 머신**이었다. 지금 국면을
기억하고 전이 규칙(더 급한 국면은 바로, 덜 급한 국면은 3턴 뒤)으로 바꿨고, 트리는 한 층짜리 목록이었다.
반대로 깃발병 이동(`flag_step`)은 "다가가기 → 대기 → 피하기" 대체 순서라 이미 BT의 Selector 모양이었는데
if-else로 적혀 있었다. 두 방식이 섞여 있어 **BT로 통일했다**. 앞으로 중반 대응을 가지로 하나씩 끼워 넣기 쉽고
(상태 머신은 상태가 늘면 전이를 모두 다시 따져야 한다), 판단 조건이 노드 이름으로 드러나기 때문이다.

- 뼈대: `Selector`(처음 성공한 자식에서 멈춤) · `Sequence`(모두 성공해야 성공) · `Condition` · `Act` ·
  `Latch`(국면 유지 = 예전 히스테리시스를 조건 노드의 장식으로). 매 턴 루트부터 한 번 평가하고, RUNNING은 없다
- 행동은 그대로다: `python -m sim diff . git:main`으로 상대 4종(같은 봇, lv2, M3, M4)·800경기·115,286턴의
  명령이 모두 같음을 확인했다. 응답 시간도 같다(최대 10 ms)
- 트리 전체는 `tree_text()`로 출력한다 (노드 이름이 곧 판단 조건):

```
→ 한 턴
  ▶ 상황 읽기 (위협 맵·건물 가치·목표 후보)
  ? 국면 선택 (위에서부터 처음 성립하는 가지)
    → THREAT
      ◇ 적 깃발병이 3칸 안에 온 우리 건물의 추정 점수 합 ≥ 2 (풀려도 2턴 유지)
      ▶ THREAT 가중치 적용
    → HOLD
      ◇ 110턴 이후이고 추정 점수가 앞섬 (풀려도 2턴 유지)
      ▶ HOLD 가중치 적용
    → ATTACK
      ◇ 우리 전투병 ≥ 적 전투병 + 2이고 상대가 건물을 가짐 (풀려도 2턴 유지)
      ▶ ATTACK 가중치 적용
    → EXPAND
      ▶ EXPAND 가중치 적용
  ▶ 점령 계획 → 점령 비용 예약
  ▶ 생산 (전투병 → 깃발병 → 남으면 전투병, 병원 위치)
  ▶ 전투병 과제 배정·이동 (역 순간이동)
  ▶ 깃발병 재배정 → 한 명씩 깃발병 트리
  ▶ 동시 점령 우선순위

? 깃발병 한 칸
  → 목표에 닿을 수 없음
    ◇ 목표까지 경로 없음
    ▶ 제자리
  ▶ 목표 쪽 안전한 칸으로
  → 대기
    ◇ 지금 칸이 안전
    ▶ 제자리
  ▶ 가장 목표에 가까운 안전한 이웃으로 피하기
  ▶ 위험해도 목표 쪽으로
  ▶ 제자리
```

결과와 한계 (로컬, M2 상대):
- M3 96승 4패. 그중 지키기 과제만으로 92승 → 효과의 대부분은 지키기 과제
- M2 상대로는 약 88%의 턴이 위협 대응이다. M2가 깃발병을 맵 전체에 흩어 보내 우리 건물 근처에 늘 적 깃발병이
  있기 때문. 기준을 엄하게 바꿔도 분포·승률이 나아지지 않아 첫 값을 유지했다
- 국면 전환이 실제로 갈리는 상대(서버 봇)에서 효과를 다시 확인해야 한다

- `choose_phase(world, memory) -> Phase` → 국면별 효용 가중치 → M1·M2 배정기
- 국면 4개(우선순위 순): 위협 대응 → 굳히기 → 공격 → 확장 (위 구조도)
- 직전 국면을 기억하고 임계값에 여유 폭(히스테리시스)을 둬 국면이 턴마다 바뀌지 않게 한다
  - `decide` 호출 사이의 상태가 필요하다. 모듈 수준 메모리 또는 `World` 필드 추가 중 선택
- stderr에 턴마다 선택한 국면을 남긴다 → 보고서 "유닛 운용" 자료

## M5. 후반 운영 + 마감

### 9/27 확인: 막판 운영은 뒤집을 경기가 적다

최근 로컬 대전 3,260경기의 결정 사유: 점령 점수 61%, 즉시 승리 20%, 무승부 16%(대부분 같은 봇끼리),

| --- | --- | --- |
| 경기 끝(160턴)까지 점령을 마칠 수 없는 (깃발병, 건물) 짝은 배정하지 않기 | `main` 상대 31.5% — 크게 나빠짐 | 못 마칠 목표로 가던 깃발병도 상대 건물·중립 건물에서 **경합**을 만들어 상대 점령을 막는다. 막판 깃발병 이동은 헛걸음이 아니었다 |

언제·왜 밀리기 시작하는지 찾는 것부터 한다.

### 9/27 진 경기 분석: 전투병 생산량 → 공학관

`python scripts/analyze_games.py git:main git:f564d8b --seeds 100` (이긴 120 · 진 76경기):

- 30턴까지는 이긴 경기·진 경기 모두 점수·건물·병력이 같다. 진 경기는 **전투병 차이가 먼저 벌어지고**
  (50턴 −7 → 80턴 −20 → 120턴 −43), 점수 차이는 그 뒤에 따라온다(80턴 −6 → 120턴 −13)
- 전투병은 전투에서 양쪽이 같은 수만큼 상쇄되므로, 살아 있는 전투병 차이 = 생산량 차이다. 생산량은 자원과
  전투병 값으로 정해지고, 그걸 바꾸는 건물이 학생회관(수입 +2)과 **공학관(전투병 값 3 → 2)**이다
- 진 경기는 30~60턴부터 공학관·학생회관·도서관 보유가 상대 쪽으로 기운다(공학관 0.85:1.04 → 100턴 이후 0.61:1.19)
- 건물은 한 경기에 양쪽 합쳐 약 60번 중립화된다(중앙 건물은 종류마다 경기당 5~6번). 한 가지 결정적 사건보다
  작은 차이가 눈덩이처럼 커지는 모양이다. 단 상대가 우리와 거의 같은 이전 버전이라는 한계가 있다

→ 공학관 기능 가치를 0.5 → 2.0으로 올렸다. `main` 상대 59.5%·62%(시드 두 묶음, 400경기). 이긴 경기에서는
첫 30턴부터 공학관을 먼저 잡는다(0.67:0.56). 학생회관 가치를 올리는 것은 효과가 없었다.
