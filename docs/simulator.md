# 로컬 시뮬레이터 (`sim/`)

처음에는 운영진이 로컬 대전 엔진을 주지 않아 규칙서대로 동작하는 엔진을 직접 만들었다. 2026-09-27에
운영진이 공식 개발도구(엔진·맵 생성기·러너, 저장소의 `devtool/`)를 배포한 뒤로는 **맵은 공식 생성기로
만들고, 우리 엔진은 공식 엔진과 매 턴 같은 상태를 내는지 테스트로 확인한다**(아래 "실제 서버와 같은가").
공식 러너가 있는데도 `sim/`을 쓰는 이유는 공식 러너에 없는 것들 때문이다: Windows에서 실행(공식 러너는
Windows에서 `WinError 10093`으로 멈춘다), 여러 판 병렬 대전과 승점률 요약, `git:` 버전 비교, 리플레이 뷰어.
용도는 두 가지다.

1. **빠른 검증**: 고친 봇이 이전 버전이나 스타터 봇보다 나은지 수십 경기로 확인한다 (`arena`)
2. **눈으로 확인**: 한 판을 리플레이 HTML로 열어 턴마다 무슨 일이 있었는지 본다 (`match`)

`sim/`은 제출 ZIP에 들어가지 않는다(`scripts/build_submission.py`는 `main.py`와 `agent/`만 담는다).

## 빠른 사용법

저장소 최상위에서 실행한다. 가상환경이 켜져 있지 않으면 `python` 대신 `.venv\Scripts\python`을 쓴다.

```powershell
# 한 판 두고 리플레이를 브라우저로 열기
python -m sim match . starter:example_lv2 --seed 3 --open

# 지금 작업 중인 봇(.)과 main 브랜치 봇을 50개 맵 × 진영 교대 = 100경기
python -m sim arena . git:main --seeds 50

# 스타터 예제 상대로 성적 확인
python -m sim arena . starter:example_lv2 --seeds 50

# 서버 모의 전투와 같은 맵 10개(공개 시드 0~9) × 진영 교대 = 20경기
python -m sim arena . starter:example_lv2 --seeds 10

# 맵만 보기
python -m sim map --seed 3
```

시드 맵은 운영진 공식 생성기로 만들므로 **같은 시드는 서버와 같은 맵**이다. 서버 모의 전투는 공개 시드
0~9를 쓴다(시작 시드 기본값이 0이므로 `--seeds 10`이면 딱 그 10개). 단 모의 전투는 우리 진영을 유지한 10경기이고 arena는
진영을 바꿔 가며 20경기를 두므로, 서버와 같은 조건만 보려면 결과에서 우리 진영 줄을 본다.

### 봇 지정

| 쓰는 법 | 뜻 |
| --- | --- |
| `.` | 지금 폴더의 `main.py` — 제출본과 같은 진입점 |
| `path/to/dir`, `path/to/bot.py` | 그 폴더의 `main.py`, 또는 그 파일 |
| `starter:example_lv1`, `starter:example_lv2` | 스타터 킷 예제 |
| `git:main`, `git:<커밋해시>`, `git:<브랜치>` | 그 커밋의 `main.py` + `agent/`를 `runs/bots/<해시>/`에 풀어서 실행 |

`git:`을 쓰면 브랜치를 바꾸지 않고 "개선 전 vs 개선 후"를 비교할 수 있다. 커밋 안 한 변경은 `.`에만
반영된다.

### 서버 맵으로 돌리기

대회 페이지에서 받은 모의 전투 리플레이(JSON)는 `data/server-replays/`에 둔다(날짜_상대_회차 폴더, 파일 이름은
받은 그대로, 내용이 똑같은 중복 파일은 빼고). 리플레이에서 서버의 실제 지형·건물·본진과 **공개된 실제 점수**를
뽑아 시뮬레이터 맵으로 쓴다(`sim/mapgen.py`의 `from_server_replay`, `load_server_maps`).

```powershell
# 서버 맵 10개(같은 지형의 리플레이는 하나로 묶음) × 진영 교대 = 20경기
python -m sim arena . git:main --maps data/server-replays

# 리플레이 한 파일의 맵에서 한 판
python -m sim match . starter:example_lv2 --map-file "data/server-replays/2026-09-27_high_01/replay.json" --open
```

- 모의 전투는 상대 봇이 달라도 같은 맵을 다시 쓴다(9/27: 모의 전투 3회 20경기 = 고유 맵 10개). 이 10개는
  공개 시드 0~9 맵과 지형·점수가 똑같다(`tests/test_official.py`). 그래서 지금 있는 리플레이로는 `--seeds 10`과
  같은 맵이 나온다. `--maps`는 리더보드처럼 시드를 모르는 새 맵의 리플레이를 받았을 때 쓴다
- 점수는 지형이 공개 시드 맵이면 그 실제 점수, 거기에 리플레이에서 공개된 점수를 합치고, 그래도 모르는 점수는
  대칭 짝 → 규칙 범위에서 시드로 채운다. `--map-file`에 INIT 블록 텍스트를 줄 때도 공개 시드 맵이면 실제 점수를 쓴다
- 본진은 리플레이 주인(`side`)의 유닛이 처음 나타난 칸에 가까운 `H`가 그 진영이다
- 새 리플레이를 받으면 같은 폴더 규칙으로 넣기만 하면 된다. `tests/test_sim_server_maps.py`가 맵 수와 규칙
  조건을 확인하므로, 맵이 늘면 그 테스트의 맵 개수를 고친다

### arena 결과 읽기

```
A 기준  승 27 · 무 3 · 패 10   승점률 71.3% (95% 구간 56%–83%)
  A가 Y일 때: 14승 1무 5패
  A가 K일 때: 13승 2무 5패
결정 사유: score 30, instant 6, occupation 4
A: 몰수 0회 · 최대 응답 45 ms (첫 턴 최대 180 ms) · 무시된 명령 0줄
```

- **승점률**은 대회 순위 방식(승 1, 무 0.5)이다. **95% 구간**이 50%를 걸치면 아직 차이를 말할 수
  없다. 이럴 때는 `--seeds`를 늘린다.
- 시드 하나마다 진영을 바꿔 두 번 둔다. 한쪽 진영에서만 지면 방향이나 좌표 처리 버그를 의심한다.
- **무시된 명령**이 0이 아니면 봇이 규칙에 어긋난 명령을 내고 있다는 뜻이다. 리플레이의 명령 목록에
  빨간 줄로 이유와 함께 나온다.
- **최대 응답**이 300 ms에 가까우면 위험하다. 서버 CPU가 더 느릴 수 있다. 여유를 보려면
  `--time-scale 0.5`로 제한을 절반으로 줄여 돌려 본다.
- 결과는 `runs/arena-<시각>/`에 `summary.txt`, `results.jsonl`, 그리고 A가 이기지 못한 경기의
  리플레이 HTML로 남는다(`--save all|losses|none`). 보고서의 "정량적 검증" 근거로 쓴다.
- `--jobs`는 동시 경기 수로, 기본은 CPU 코어의 절반이다. 너무 올리면 CPU가 모자라 가짜 시간 초과가 난다.

### 리플레이 뷰어

`match` 또는 `arena --save`가 만든 `.html`은 인터넷 없이 브라우저로 열린다. 파일 하나에 경기 전체가
들어 있어 팀 채팅에 그대로 보낼 수 있다.

- ← → 한 턴씩 · Space 재생/정지 · Home/End 처음/끝 · 점수 그래프 클릭으로 이동
- 주소 끝의 `#t=37`을 바꾸면 그 턴으로 바로 열린다 (장면 공유용)
- 칸에 마우스를 올리면 건물 종류·점수·소유·양 팀의 점수 공개 여부·유닛이 보인다
- 오른쪽에는 그 턴에 양 팀이 낸 명령(무시된 줄은 빨강, 일부만 처리된 줄은 주황), 전투·점령 이벤트,
  봇의 stderr 출력이 나온다. 디버깅 로그는 stderr로 찍으면 여기서 턴별로 볼 수 있다

#### 팀 시점 보기 — 우리 봇이 실제로 아는 정보만

오른쪽 위 **보기**에서 `관전자 / Y 시점 / K 시점`을 고른다. 봇의 판단이 이상해 보일 때 "그 순간 봇이
알 수 있었던 정보로는 합리적이었나"를 확인하는 용도다.

이 게임에서 숨은 정보는 **건물 점수**와 **상대가 이번 턴에 낸 명령**뿐이다(규칙서 9장). 유닛·자원·
소유권은 원래 양쪽에 공개이므로 그대로 보인다. 팀 시점에서 바뀌는 것:

| 항목 | 팀 시점 표시 |
| --- | --- |
| 건물 점수 | 공개된 것만 `2점`, 대칭 짝이 공개돼 추론 가능한 것은 `2점*`, 광장은 규칙상 `3점`, 나머지 `?점` |
| 점수 표·그래프 | 아는 점수만 더한 값과 모르는 건물 수 (`12 + ?×2`). 누적 점령-턴은 입력에 없으므로 `–` |
| 상대 명령·이동 화살표·stderr | 숨김 (상태 변화로 드러나는 생산·전투·점령 이벤트는 표시) |
| 상대의 "자원 부족으로 점령 대기" | 숨김 (밖에서는 경합이나 대기와 구별할 수 없음) |
| 입력 원문 | 그 상태에서 봇이 받는 `TURN` 블록 그대로 (0턴은 `INIT` 포함) |

- 주소에 `&v=Y`를 붙이면 그 시점으로 열린다 (`...html#t=37&v=Y`)
- `python -m sim match . starter:example_lv2 --view Y --open` — 처음부터 Y 시점으로 연다
- `arena --save`로 저장한 리플레이는 평가 대상 A(보통 우리 봇)의 시점으로 열린다
- 추론은 대칭 짝과 광장만 한다. 맵 총점이 홀수라는 사실 같은 더 깊은 추론은 봇마다 다르므로 넣지 않았다

## 실제 서버와 같은가 — 검증한 것과 못 한 것

운영진 공식 개발도구(`devtool/`, 게임 커밋 `88a77d8`)는 서버 리플레이의 프로토콜 버전
(`platform-protocol-88a77d888a15`)과 같은 커밋이다. 그래서 **공식 엔진·생성기와 같은지**를 가장 강한 기준으로
삼는다. `pytest tests/test_official.py`로 다시 돌릴 수 있다.

### 규칙서만으로는 알 수 없어 우리가 정한 해석

엔진의 `ASSUMPTIONS`(`sim/engine.py`)에 모아 두었다. 리플레이 파일에도 같이 저장된다. 공식 엔진이
나온 뒤 아래 해석은 **모두 공식 엔진 동작과 같다고 확인됐다**(위 비교 테스트).

- 자원이 모자라 점령 못 한 건물은 건너뛰고, 순서상 다음 건물 중 비용을 낼 수 있는 것은 진행한다
- TELE 인원이 5를 넘으면 5명까지만 옮긴다. 출발·도착이 같은 역이면 무효
- PRIORITY가 여러 줄이면 형식이 맞는 마지막 줄을 쓴다
- 중앙광장 점수도 공개 전에는 `-1`로 보낸다 (항상 3점이라 봇은 알고 있어도 된다)
- 상대 본진 칸은 들어갈 수 있고 특별한 효과가 없다
- 출력 한도 초과는 몰수패로 처리한다. 서버도 몰수다(`devtool/docs/PLATFORM_OPERATIONS.md`). 공식 로컬
  러너는 경고만 하므로 이 점은 우리 쪽이 서버에 더 가깝다

공식과 **다른 점 하나**: 공식 파서는 숫자를 `int()`로 읽어 `+3`, `1_0` 같은 표기도 받지만 우리 파서는 무효로
본다. 봇이 그런 표기를 낼 일이 없어 그대로 두고 비교 테스트에서도 뺐다.

### 아직 모르는 것

- **리더보드·최종 평가 맵.** 모의 전투는 공개 시드 0~9로 확인됐지만, 리더보드가 어떤 시드를 쓰는지는 공식
  문서에도 없다(game-api.md 11절 질문). 시드 0~9에서만 잘 되는 전략이 되지 않도록 arena는 `--seeds 50`처럼
  넓게도 돌린다.
- **서버 CPU 속도.** 시간 제한은 우리 PC 기준이다. `--time-scale 0.5`로 여유를 본다.

## 구조

```
sim/rules.py    규칙 수치 (agent/의 상수를 일부러 쓰지 않는다 — 봇과 엔진이 같은 실수를 공유하지 않게)
sim/official.py 운영진 개발도구(devtool/)를 불러오는 유일한 창구: 공식 생성기·엔진·직렬화
sim/mapgen.py   시드 맵(공식 생성기), INIT 블록·서버 리플레이 읽기
sim/engine.py   한 턴 처리(생산→이동→전투→수입→점령→공개→판정), 봇에게 보낼 블록 만들기
sim/bots.py     봇 프로세스 실행, 시간 제한·END·출력 한도 확인
sim/match.py    한 판 진행 + 리플레이 기록
sim/arena.py    여러 판 병렬 실행, 요약 통계
sim/viewer.*    리플레이 HTML
```

속도: 스타터 봇끼리 한 판 약 0.1~0.3초, 40경기 아레나 약 1초(24코어 기준). 우리 봇이 무거워지면 그만큼 늘어난다.
