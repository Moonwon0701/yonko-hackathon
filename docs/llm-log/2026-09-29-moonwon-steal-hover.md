## 범위 — LLM이 한 것

- 리플레이 분석(일회용 스크립트, 저장소에 넣지 않음):
  - 자원 흐름: 전투병은 1:1 상쇄라 전투병 수 차 = 누적 생산 차. 진 5판 21~80턴 생산 격차 42~83명, 수입(학생회관)과 전투병 값(공학관)으로 나눔
  - 경제 건물을 잃은 56번 분류: 빈 건물 30번(적 전투병 없이 깃발병 혼자), 상쇄 패배 23번(옆 칸에 쌓다가 동수에 들어옴). 9/29 10:00 회차는 11·16번
  - 제출본(`7941b88`)에 리플레이 상태를 순서대로 넣어 판단을 재현(세 판 모두 매 턴 서버 명령과 같음): 붉은 산호초전 17턴(점령한 깃발병이 떠난 뒤 전투병 0, 지키기가 3걸음에서 켜져 늦음), 참새튀김기전 32턴(필요 12명 계산, 증원이 2걸음 밖), 탈락도전 57·59턴
  - 운용 지표: 20~80턴 진 경기 우리 전투병의 32%가 건물에서 떨어진 우리 진영 칸에서 평균 8.4걸음 떨어진 목표로 이동 중(이긴 경기 21%·5.2걸음, 상대 12~13%), 목표는 처치 22%·별동대 14%·탈환 14%·러시 13%. 10~50턴 전투 뒤 상대만 남은 비율 46~75%(우리만 5~32%). 국면은 92~100% 위협 대응
- `opponents/steal.py` (새 파일): 상대 소유이고 3걸음 안에 상대 전투병이 없는 건물의 점령 가치를 올리는 흉내 봇
- `opponents/hover.py` (새 파일): 상대 학생회관·공학관 옆 칸에 전투병을 모았다가 건물 위 인원 이상이 되면 들어가는 흉내 봇
- `agent/strategy.py`: 스위치 5개(모두 기본 끔) — `ECON_GARRISON`·`GARRISON_VALUE`(경제 건물 상주), `ECON_GUARD_RADIUS`(경제 건물 깃발병 경보 반경), `DEFEND_MARGIN`(경제 건물 방어 인원 여유), `KILL_REACH`(먼 적 깃발병 쫓지 않기), `ATTACK_TIE`(우리 깃발병이 가까우면 급습·러시 인원을 동수로, `attack_need`)
- `opponents/steal.py` 강도 조정(3걸음 → 2걸음, 가치 ×4 → ×6, 깃발병 4 → 5명). `hover.py`는 강하게 바꾼 설정이 오히려 약해 원래대로 둠
