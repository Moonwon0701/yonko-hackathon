# 공식 개발도구를 저장소에 넣고, 시뮬레이터를 공식 맵 생성기·엔진과 맞추기

- 날짜: 2026-09-27
- 요청한 사람: 문원
- 모델: Claude Opus 5.5 (`claude-opus-5-5`), Claude Code CLI
- PR: #30 (브랜치 `moonwon/official-devtool`)

## 프롬프트 (원문 그대로)

1. > dev_tool 확인해줘. 이거 배포된 개발도구야.
2. (운영진에게 보낸 맵 관련 질문 3개를 붙여 넣음 — 모의 전투 맵이 고정인지, 리더보드·최종 평가 맵은 무엇인지,
   관찰한 맵 정보를 소스 상수로 쓰는 것이 허용되는지. 내용은 `docs/game-api.md` 11절 "맵 구성" 1~3과 같다)
   > 이런 질문 했는데 전부 답이 되나? 그리고 우리 시뮬레이터는 그럼 필요가 없나?
3. > 오늘은 내가 단독개발이니까 결정없이 진행해도 괜찮아. 제안대로 진행해줘

## 목적

- 운영진이 배포한 `dev_tool.zip`이 무엇이고, 우리 규칙 문서·시뮬레이터와 어디가 같고 다른지 확인
- 보낸 질문 중 개발도구로 답이 나오는 것과 여전히 물어야 하는 것을 가르기
- 시뮬레이터가 서버와 같은 맵에서, 서버와 같은 규칙으로 돌도록 만들기

## 범위 — LLM이 한 것

- 조사 (1·2번 프롬프트, 파일 수정 없음)
  - zip 구성 파악: 공식 엔진(`engine/`), 맵 생성기(`mapgen/`), 러너(`runner/`), `balance.json`, 규칙서, 스타터 킷
  - 규칙서를 `docs/rules-original.md` B장과 비교 → 서식만 다르고 문구 동일. 파이썬 스타터 파일은 `starter/`와 동일
  - 공식 엔진 코드를 `sim/engine.py`와 줄 단위로 읽어 비교 → 규칙 처리와 우리 가정(`ASSUMPTIONS`)이 모두 같음
  - 공식 맵 생성기는 우리 생성기와 난수·배치 방식이 달라 같은 시드라도 맵이 다름을 확인
  - 공식 러너가 Windows에서 `WinError 10093`으로 멈추는 원인(파이프에 `selectors` 사용) 확인
  - 질문 1은 개발도구 문서로 답이 됨, 2·3은 여전히 물어야 함. 3에는 "공개된 생성기로 시드를 역추적해 점수를
    계산하는 것도 허용되는가"를 덧붙이자고 제안
- `devtool/`: `dev_tool.zip`을 고치지 않고 그대로 풀어 넣음 (46개 파일)
- `sim/official.py` (신규): 공식 코드를 불러오는 유일한 창구. 공식 생성기·엔진·명령 파서·입력 직렬화
- `sim/mapgen.py`: `generate(seed)`를 공식 생성기로 교체하고 자체 생성 코드 삭제. 지형이 공개 시드 0~9 맵이면
  INIT 블록·서버 리플레이로 만든 맵에도 실제 점수를 채우는 `public_scores` 추가
- `tests/test_official.py` (신규)
  - 서버 모의 전투 리플레이 19개가 공개 시드 0~9 맵과 지형·건물·공개 점수까지 같은지
  - 우리 엔진과 공식 엔진에 같은 명령을 넣고 매 턴 INIT·TURN 블록(양 팀)·누적 점령-턴·결과를 글자 단위로 비교.
    명령은 스타터 봇끼리, 우리 봇 대 스타터, 무작위 명령(잘못된 줄 포함), 점령 자원 부족 시나리오에서 뽑음
  - `devtool/`이 운영진이 적어 둔 해시와 같은지(고치지 않았는지), 공식 `balance.json`이 스타터 `BALANCE`와 같은지
- `pyproject.toml`: ruff 검사에서 `devtool/` 제외
- `sim/engine.py`: 설명 주석을 "공식 엔진과 테스트로 비교함"으로 갱신
- `docs/simulator.md`: 머리말(공식 도구가 있는데도 sim을 쓰는 이유), 시드 0~9 = 모의 전투 맵 사용법, 검증 표에
  공식 비교 결과 추가, 가정이 모두 확인됐다고 정리, 구조에 `sim/official.py` 추가
- `docs/game-api.md`: 11절 질문 중 공식 엔진 코드로 답이 나온 7개 해결 표시(상대 본진 진입, 생산 유닛 전투,
  즉시 승리 기준, 자원 부족 시 건너뛰기, TELE 5명, 광장 -1, TURN 1~160), 맵 질문 1에 검증 결과, 질문 3에 덧붙일 내용,
  12절 변경 기록
- `CLAUDE.md`: 구조 규칙에 `devtool/`(고치지 않음, `sim/official.py`만 불러옴) 추가

## 사람이 한 것

- `dev_tool.zip`을 대회 페이지에서 받아 저장소 옆에 둠
- 운영진에게 맵 관련 질문 3개를 작성해 보냄
- `devtool/`을 저장소에 넣고 시뮬레이터를 바꾸는 것을 결정(9/27 단독 작업일이라 팀 논의 없이 진행하기로 판단)
- 조사 중 Claude Code가 공식 러너를 바로 실행하려던 것은 자동 권한 검사에서 막혔고, 이후 문원이 제안대로
  진행하라고 지시해 공식 코드를 테스트에서 실행함

## 검증

- 서버 리플레이 19개 ↔ 공식 생성기 시드 0~9: 지형·건물·공개 점수 **불일치 0**
- 엔진 비교: 스타터 봇 10경기, 우리 봇 10경기, 무작위 명령 30경기(점령 1,013·TELE 834·깃발 뽑힘 378·경합 352·
  중립화 259·보급소 78회), 자원 부족 20경기(점령 대기 110회) — 매 턴 **전부 일치**
- 공식 생성기 시드 300개가 규칙서 1장 조건을 모두 만족(기존 테스트를 공식 생성기에 그대로 적용)
- 전체 테스트 통과, `ruff check sim tests/test_official.py` 통과
- 알려진 차이 하나: 공식 파서는 `+3`, `1_0` 같은 숫자 표기도 받고 우리 파서는 무효로 본다. 봇이 낼 일이 없어 비교에서 뺌
